2. API health with LibreOffice available.
3. PDF information, including two-page count.
4. Merge, reorder and rotate pages, preserving text and rotation.
5. Split into two valid PDF members of a ZIP archive.
6. Page numbering, start number, formatting and position.
7. Centered watermark insertion.
8. Tiled watermark insertion.
9. PNG, JPEG and WEBP input into a three-page PDF.
10. PDF to PNG export with ZIP members and 96 DPI.
11. Compression without enlarging or corrupting a PDF.
12. PDF to Word with valid DOCX and source text.
13. Word to PDF with valid PDF and source text.
14. Editor native element discovery.
15. Editor added-text overlay export.
16. Editor native source-text replacement.
17. Invalid PDF rejection with HTTP 400.

Homepage and deep-link routing are separate checks, for 18 total.

The first small-document Word to PDF request completed in **1.74 seconds**.
This is only a sample latency, not an SLA or benchmark. The previously reported
missing-LibreOffice HTTP 503 was not reproduced.

## Limits — do not overinterpret these checks

These tests do **not** guarantee every possible PDF or Word document works.

- Complex Word layouts, tables, fonts, comments, tracked changes, form fields,
  encrypted documents, scanned images and exact page-fidelity were not audited.
- Extreme file sizes, high concurrency, memory pressure, 600-DPI large PDFs,
  rate limits, fault tolerance and security isolation were not stress-tested.
- Native original-object editing remains experimental for complex PDFs.
- Browser tests confirm normal controls and download signatures. API tests
  separately inspect document contents; they do not prove perfect visual layout.
- Mobile layout, accessibility and cross-browser fidelity require further review.
- Vulnerability, dependency licensing and data-retention audits remain separate.
